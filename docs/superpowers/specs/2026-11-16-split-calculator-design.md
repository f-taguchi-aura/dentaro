# Montaro 電卓 v1 設計（アプリ本体）

## 目的・背景
- 自分用。事業の KPI 計算で、2つの独立した電卓を同時に使いたい。
- 「2つ並べて別々に動かせる」ことが核。電卓間の連携は不要。
- 追加モードとして「単価比較」（容量と値段から最安を判定）を持つ。

## ゴール
1. 1画面を2分割し、それぞれ独立して操作できる電卓（縦向き=上下、横向き=左右）。
2. 画面上部の切り替えで「電卓×2」⇔「単価比較」モード。
3. モダン・モノクロ基調・シンプルなUI。ライト/ダーク両対応。
4. iPhone / Android 両対応。

## 非ゴール（v1 ではやらない）
- ウィジェット（ホーム画面・通知欄）→ 第2段階で別設計。
- 電卓間の値の受け渡し、関数電卓機能、履歴一覧画面。
- 単価比較での単位換算（g↔kg 等）。
- 広告・課金・ストア公開。

## アンチゴール（動いても失敗とみなすもの）
- キー入力の遅延・取りこぼし。片方の操作がもう片方に影響する。
- 0.1 + 0.2 = 0.30000000000000004 のような浮動小数点誤差が表示される。
- ボタンや装飾が多くてごちゃつく。

## 制約
- 既存の Expo（SDK 58, Expo Router, TypeScript）プロジェクト上に構築。
- v1 は Expo Go で動く範囲（ネイティブ追加モジュールなし）に収める。
- `npm run typecheck` / `npm run lint` が通ること。

## 作り方の検討（Approaches）
- **A. 既存 Expo プロジェクトに画面を追加（採用）**：計算ロジックを純粋な TS モジュールにし単体テスト、各ペインは独立した状態を持つ。第2段階のウィジェットも同じプロジェクトにネイティブターゲットとして追加できる。
- B. Swift / Kotlin でネイティブ別実装：ウィジェットとの親和性は高いが、コード量が約2倍。v1 には過剰。
- C. Web アプリ（PWA）：ウィジェット化できず、第2段階につながらない。
- ユーザーは作り方を任せたため、A を Claude の判断で選択。

## 決まった仕様（ユーザー合意済み）
- 2分割の独立電卓。連携機能なし。
- 単価比較を別モードとして同じアプリに入れる。
- ウィジェットは後回し。

## Claude の判断（提案・レビューで変更可）
### 電卓
- キー：`0-9` `.` `+ − × ÷` `%` `⌫` `AC` `=`（必要に応じ `±`）。
- 入力中の式を表示（例 `12,500 × 3.2%`）し、下に結果をプレビュー。
- 演算子の優先順位は通常の数式どおり（× ÷ が先）。
- `%` の挙動：`a × b%` = a×b/100、`a + b%` = a + a×b/100（一般的な電卓と同じ）。
- 小数は 10 進演算ライブラリ（例：decimal.js / big.js）で誤差を出さない。
- 3桁カンマ区切り。表示桁が溢れたら文字を縮小。
- 両ペインの状態（式・結果）とモードを端末に保存し、再起動後も復元。

### 単価比較
- 行 = 名前（任意）・価格・容量。最低2行、最大6行程度、追加/削除可。
- 単位は全行共通のラベル1つ（ml, g, 個 など自由入力）。換算はしない。
- 各行に「1単位あたり価格」を表示し、最安の行を強調（★）。
- 入力は OS の数字キーボード。

### デザイン
- 白黒グレーの基調＋アクセント1色（演算子・最安表示のみ）。
- 角丸の大きめキー、細めの数字フォント、余白多め。
- 2ペインの境界は細線のみ。操作中のペインをわずかに強調。

## 第2段階（ウィジェット）への備え（ユーザー合意済み）
- ウィジェットはアプリとは**別の独立した電卓**。アプリと状態を共有しない → v1 の保存先は通常のアプリ内ストレージでよい（App Group 不要）。
- Bundle ID / パッケージ名は `jp.montaro.app` で確定。
- iOS ウィジェットは Swift で計算ロジックを再実装することになるため、v1 の計算ロジックのテストケースは**言語非依存のデータファイル**（例：`src/calc/test-vectors.json` に `{入力キー列, 期待される表示}` の配列）として持ち、TS のテストはそれを読み込んで検証する。将来の Swift 実装も同じファイルで検証する。
- 計算ロジックは UI から独立した純粋関数（キー入力 → 新しい状態）として実装する。

## ビルダーに任せる部分
- 状態管理の具体的な実装、保存先ライブラリ（AsyncStorage 等）の選定。
- 10 進演算ライブラリの選定、フォント、細かな配色・余白・アニメーション。
- ファイル構成（`src/app` は画面のみ、ロジックは `src/` 配下）。
- 計算ロジックの単体テスト環境（jest-expo 等）。
